Supplier Watch API

A read-only JSON API for the Pro and Accountant plans: your suppliers, their latest check results and your alerts, for your own systems (ERP, accounting, dashboards).

Authentication

Create a key on your manage page (API keys section). It is shown once; we store only a hash. Send it as a Bearer token:

curl -H "Authorization: Bearer sw_..." https://supplierwatch.cz/api/v1/suppliers

You can have up to 5 active keys and revoke any of them at any time. A revoked key stops working immediately.

Limits

60 requests per minute per key. Every response carries X-RateLimit-Limit and X-RateLimit-Remaining; over the limit you get 429 with Retry-After (seconds). Data change once a day (checks run at 06:30 Prague time), so polling more than a few times a day isn't useful.

Endpoints

EndpointReturns
GET /api/v1/accountYour plan, supplier limit and counts
GET /api/v1/suppliersAll suppliers with their latest results. Filters: status=ok|alert|failed|pending, client=<id> (or main). Paginated.
GET /api/v1/suppliers/{ico}One supplier (8-digit IČO). If the IČO is on several client lists, the others are in also_in; use client= to pick one.
GET /api/v1/alerts?since=2026-10-01Check results with an alert, a change or a failed source since the given ISO 8601 date or time (default: last 30 days, at most 24 months back), newest first. Filter: client=. Paginated.
GET /api/v1/clientsAccountant plan: your client lists with supplier counts. Paginated.
GET /api/v1/sourcesLatest daily self-check of each data source

Pagination

List endpoints take limit (1 to 200, default 50) and offset (default 0) and return:

{ "data": [ ... ], "pagination": { "limit": 50, "offset": 0, "total": 312, "next_offset": 50 } }

next_offset is null on the last page.

Supplier object

{
  "ico": "27082440",
  "client": null,                      // or { "id": "cl_...", "name": "Novák s.r.o." }
  "website": "alza.cz",
  "name": "Alza.cz a.s.",
  "last_checked": "2026-10-21T04:30:12.000Z",
  "status": "ok",                      // ok | alert | failed | pending (not checked yet)
  "checks": {
    "ares":     { "status": "ok", "detail": "registered: ..." },
    "vat":      { "status": "ok", "detail": "not unreliable (PLATCE_DPH)" },
    "accounts": { "status": "ok", "detail": "3 published accounts" },
    "isir":     { "status": "ok", "detail": "no proceedings" },
    "coi":      { "status": "ok", "detail": "alza.cz not listed" }
  },
  "alerts": [],                        // e.g. "UNRELIABLE_VAT_PAYER", "INSOLVENCY_PROCEEDING"
  "changes": []                        // e.g. { "type": "BANK_ACCOUNT_ADDED", "to": "123/0100" }
}

Check status is ok, alert, failed (the source did not answer or failed our daily self-check, so no result is claimed), not_run (not applicable, e.g. no website) or invalid. Times are UTC.

Errors

Errors always look like this:

{ "error": { "code": "invalid_api_key", "message": "API key not recognised." } }
HTTPcodeMeaning
400invalid_parameter, invalid_icoBad query parameter or IČO
401missing_api_key, invalid_api_key, revoked_api_keyNo key, unknown key or revoked key
403plan_required, account_not_confirmedYour plan doesn't include the API (or client lists)
404not_foundUnknown endpoint, or the IČO/client isn't on your account
405method_not_allowedThe API is read-only; use GET
429rate_limitedToo many requests; wait Retry-After seconds

Each key only ever sees its own account's data. Questions: contact@supplierwatch.cz.
